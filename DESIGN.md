# Seed Slash design system

## Overview

Seed Slash is a casual, single-screen arcade game for touch, mouse and keyboard. Its visual idea is a friendly woodland snack run: a dark layered forest frames warm golden game lettering and Pip, a round hamster with a green scarf. The source of truth is `src/styles.css`, the screen composition in `src/App.tsx`, and the original vectors generated by `scripts/make-art.mjs`.

The desktop start screen pairs the action and title on the left with Pip on the right. Phones put the product and Start slicing first, with the mascot and three illustrated rules below. Gameplay replaces that composition with a full-viewport canvas and stable controls; it is not a scrolling marketing page.

## Colors

Canonical interface colors are hexadecimal CSS custom properties at the top of `src/styles.css`. Components use role tokens pointing to primitives. The artwork has a separate, deliberately broader illustration palette embedded in its SVGs.

| --- | --- | --- |
| `--bg` | `#0d2522` | Page base and the protected footer reading area |
| `--surface` | `#173b33` | Tutorial/bonus dialogs and pause symbol |
| `--surface-hover` | `#254c3c` | Utility and secondary action hover |
| `--text` | `#fff1ce` | Headings and primary score text |
| `--text-secondary` | `#c6d0b7` | Body copy, instructions, status and supporting values |
| `--text-muted` | `#a6b99c` | Secondary decoration and desktop footer note |
| `--accent` | `#f8c85a` | Filled primary action, golden score/seed identity |
| `--accent-hover` | `#ffe39a` | Primary action hover |
| `--on-accent` | `#423018` | Text and icons on the gold button |
| `--focus` | `#ffe39a` | 2px visible keyboard focus ring |
| `--danger` | `#efa58c` | Remaining life hearts |
| `--success` | `#acd19d` | Running-wheel status dot |
| `--border` | `#3b5947` | Structural divider in the keyboard tutorial |

Primitive ramps are `--forest-950/800/700`, `--cream-100/300/500`, `--gold-200/400/900`, plus rose and leaf status primitives. This is one intentionally dark theme; there is no light-theme switch.

The primary action is gold and has a distinctive solid shape. Gold also belongs to the requested cartoon art direction and golden-seed mechanic; it is not the sole indicator of interactivity or status. Lives have a numeric accessible label, and wheel states have words alongside their dots.

The gameplay footer has a dark edge gradient reaching opaque `--bg` at 46%, so launch effects cannot make its status unreadable. Measured foreground/background center samples are preserved in `artifacts/contrast-*.json`; the limits of that sampling are in `artifacts/validation.md`. Do not assume a contrast ratio for an arbitrary animated canvas pixel.

## Typography

Two local font families, no runtime font requests:

| Family | Files / weights | Roles |
| --- | --- | --- |
| Lilita One | `public/fonts/lilita-latin.woff2`, normal 400 | Game wordmark, brand, state headings, score numerals and canvas combo lettering |
| Nunito | `public/fonts/nunito-latin.woff2`, variable normal 400–800; UI uses 400, 700, 800 | Body copy, buttons, labels, instructions and statistics |

Nunito falls back to `ui-rounded, system-ui, sans-serif`; display type falls back to sans-serif. Both faces use `font-display: swap`. Synthesis is disabled. Body line-height is 1.5, longer desktop intro copy 1.6, dialog descriptions 1.5–1.6, state headings 1.1, and the short display wordmark 0.92 (0.9 on phones). Root font smoothing is declared once.

| Token | Default | Use |
| --- | --- | --- |
| `--text-sm` | 14px / .875rem | Supporting UI and captions |
| `--text-body` | 16px / 1rem | Standard prose and compact headings |
| `--text-lead` | 20px / 1.25rem | Primary buttons, desktop subtitle, strong stats |
| `--text-heading` | 28px / 1.75rem | Dialog headings and canvas combo messages |
| `--text-state` | 48px / 3rem | Pause/game-over headings and current score |
| `--text-display` | 96px / 6rem | Start title and final score; 64px below 48rem |

At widths below 23rem the title uses the existing 48px scale step. Short desktop landscape screens also use a 48px display token. At most six size roles exist, with fewer used on any one start screen. The desktop wordmark is two lines; on phones it becomes one line. Its only tracked display style is `letter-spacing: -.025em`; body and UI labels have natural tracking. Headings balance wrapping, prose uses pretty wrapping, and the intro is limited to 32ch. Changing numeric values use tabular numerals. Critical values are not ellipsized.

## Layout

The spacing scale is 4, 8, 12, 16, 24, 32 and 48px (`--space-1/2/3/4/6/8/12`). Components use these values and specific illustration dimensions. Related information groups within 8–12px; separate groups usually have 24px or more. Use logical padding, margin and inset properties for interface alignment; canvas coordinates remain physical because a swipe follows physical screen positions.

`.app` is an isolated flex column with a minimum of `100svh`. `.home-main` has a 1220px maximum width; `.home-content` uses `.9fr 1.1fr` columns with a 20px gap. Header/footer controls stay inside desktop 40px or mobile 20px safe-area-aware insets. `.home-main` has 56px desktop inline padding, reducing to 40px and then 24px/16px.

Breakpoints in `src/styles.css`:

- **70rem:** reduce the copy inset and outer desktop spacing.
- **48rem:** stack the start composition, make the title one line, center the action, shrink Pip to at most 290px, show rule illustrations above their captions, and hide the nonessential help text/desktop footer note. Game stats compress without losing score, combo or lives.
- **23rem:** use the 48px title step, 16px gutters and more compact dialog/rule spacing.
- **48rem and 47rem height conditions:** reduce mascot/rule spacing on short desktop and portrait screens; the compact phone mascot is 240px, with its caption clear of the stump.
- **40rem height:** hide the decorative result mascot and reduce result spacing so replay stays reachable.
- **36rem height on desktop-width landscape:** shrink the display to 48px, reduce header and copy spacing, and keep Start slicing within the first screen.

Gameplay uses exactly `100svh` and locks document scrolling. `.play-main` and the canvas fill the screen. The flex footer uses `margin-block-start:auto`, while HUD/controls sit above the canvas. The Canvas `ResizeObserver` resizes its backing store to at most 2× device pixels and rescales active entities without restarting the round.

Actual browser checks cover 320×740, 390×844, 390×640, 768×1024, 844×390 and 1440×900. The Start button's bottom was 302px at 390×844. Native zoom and physical safe-area devices remain unverified.

## Elevation & Depth

The forest SVG supplies the background depth; a vignette protects the edges. Pip uses a soft decorative drop shadow. The title's two hard shadows (`0 5px #7e552f`, `0 9px #142f26`) give it a cartoon cutout effect.

`.primary` has a 5px warm lower edge and a soft 10px/24px shadow, without a border. Dialogs use a 24px/90px shadow and a dark blurred backdrop, without an additional border. Structural borders are reserved for dividers and keycaps. Pause/result overlays use `#0d2522e8`. Stacking is forest −3, vignette −2, scene/canvas 1, HUD 2, state overlays 4, header/footer 6, then the native dialog top layer.

## Shapes

The principal button radius is `--radius:16px`. Utility and text buttons use 12px radii, desktop dialogs 28px, mobile dialogs 24px, keycaps 5px, and dots/life or pause decorations use rounded or circular forms. Illustrations have their own organic shapes, outlines and shading; they are not UI card surfaces.

## Components

| Component / pattern | Source | Behavior and states |
| --- | --- | --- |
| `App` screen state | `src/App.tsx` | Home, playing, paused, game over; first-run tutorial; best score and sound state |
| `.primary` | `src/styles.css` | One filled primary action per view; lighter hover, 0.96 pressed scale, 2px focus ring; no movement with reduced motion |
| `.icon-button`, `.help-button`, `.text-button` | `src/styles.css`, `src/Icon.tsx` | Native buttons with 44px minimum targets; labelled icons; solid neutral hover; active/focus feedback |
| `Modal` | `src/Modal.tsx` | Native modal dialog, semantic heading, close button, backdrop dismissal, Escape, browser focus containment and explicit focus restoration; content scrolls within viewport |
| `Game` | `src/Game.tsx` | Pointer capture, primary finger/left mouse drag, keyboard lane cuts, blur/visibility pause, live canvas resizing, retry UI for artwork/canvas failure |
| HUD | `src/App.tsx` | Named stats group; tabular score; text plus icon combo state; named aggregate life graphic; stable drop counter |
| `WheelLabel` / `.wheel-button` | `src/App.tsx`, `src/wheel.ts` | Checking, live resting, live running and clearly local states; info dialog and connection retry; no stale live state |
| Pause/result state | `src/App.tsx` | Focus goes to Resume or Play again; local best/round statistics; storage failure is explained in place |
| Renderer | `src/game/renderer.ts` | Original nut sprites, clipped sliced halves, particles, numeric feedback, glowing segmented trail and keyboard lane highlight |

`.primary` and utility actions explicitly transition background, color and transform for 150ms using `cubic-bezier(.2,0,0,1)`. There is no `transition:all`. Home nuts bob by only 5–6px over five seconds under `prefers-reduced-motion:no-preference`. Under reduced motion, decorative orbit animation and button scaling stop, canvas glow/flash and loose particles are reduced; necessary nut trajectories remain. Controls have static labels/colors independently of animation.

Only the gesture-driven canvas disables selection and touch scrolling. Instruction and status text remain selectable. The canvas supplies a keyboard-control name and description; a stable polite region announces lives, pause and the final result, without announcing each high-frequency score change.

## Do's and Don'ts

- Reuse the semantic colors and six type roles; keep new supporting text at 14px or above.
- Start additional utility surfaces with `Modal` and the existing spacing. Keep a single gold primary action and descriptive secondary controls.
- Preserve the protected footer reading area and keep floating chrome out of the HUD. Test the live canvas behind any new text.
- Keep the product and Start slicing visible at 390px and test short landscape layouts after changing copy.
- Bundle new runtime artwork locally. Preserve the original vector style and warm outlines instead of adding unrelated stock imagery or extra card systems.
- Keep local game behavior and external telemetry visibly distinct. Never turn unavailable, stale or simulated data into a live wheel label.
- To add a new informational view, use a heading, a short plain description and native buttons inside `Modal`; reuse the above tokens and keyboard handling, then check mobile wrapping, contrast, focus return and reduced motion.
